**1. 텍스트 분석이 아니라 구조화된 노동데이터 크로스체크**
공고 텍스트에서 "느낌"으로 편향 점수 매기지 말고, 실제 그 회사의 **재직자 연령/근속 분포**를 근거로 써. 크레딧잡, 잡플래닛 재직자 리뷰, 공시자료(사업보고서의 평균근속연수·평균연령 항목은 상장사면 공시 의무 있음)에서 긁어와서 "이 회사는 실제로 40대 이상 재직자 비율이 X%다"를 공고 텍스트 신호랑 결합. 이게 핵심 차별점인 이유: LLM 추측이 아니라 **검증 가능한 데이터 기반 근거**라서 신뢰도가 다르고, 기술 스택도 NLP+데이터 크롤링/공시 파싱이 붙어서 "그냥 프롬프팅"이란 반박이 안 먹힘.

**2. 이력서 첨삭이 아니라 "구세대 직무언어 번역기"**
40-50대 재취업 실패의 진짜 원인 중 하나는 스킬이 없어서가 아니라 **본인 경력을 요즘 JD 언어로 못 옮겨서**야. "전산실 담당" ≠ "IT 인프라 관리", "영업관리" ≠ "B2B 어카운트 매니지먼트" 같은 세대 간 직무 용어 갭. 이건 아무도 안 만든 좁은 문제고, "이력서 첨삭 AI"라는 뻔한 카테고리에서 벗어나 **legacy job title/skill vocabulary → 현재 JD 언어 매핑기**라는 구체적 기술 문제로 재정의됨. 데모로 "옛날 표현 → 지금 표현" before/after 보여주면 훨씬 각인됨.

[이윤지] [오후 2:49] # 위치 기반 실종 시민 제보망 제안서

## 1. 서비스명

**NearFind (가칭)**  
잊히는 실종 문자를, 현장에서 알아보고 행동하게 만드는 AI 기반 공공안전 시민 제보망

### 공공 프로젝트 방향

NearFind는 민간 수익 서비스가 아니라 경찰청·지방자치단체·실종 대응기관에 제공하는 **공공안전 보완 플랫폼**을 지향한다. 기존 실종경보 문자를 대체하기보다, 공식 경보의 도달 정확도와 시민 제보 전환율을 높이는 보완 채널이다.

Codex Community 해커톤에서는 OpenAI를 활용해 텍스트형 실종 정보를 시민이 현장에서 즉시 이해하고 안전하게 행동할 수 있는 정보로 전환한다는 점을 보여준다.

## 2. 문제 정의

현재 실종 안내 문자는 많은 사람에게 한 번에 전달되지만, 수신자는 다음 문제를 겪는다.

- 문자 속 인상착의가 텍스트 중심이라 실제 현장에서 기억하고 알아보기 어렵다.
- 현재 위치와 무관한 정보가 대부분이어서, 수신 직후 확인하지 않으면 잊히기 쉽다.
- 수색이 필요한 지역을 지나는 시민에게 적절한 시점에 다시 도달하지 못한다.
- 모든 사람에게 동일한 알림을 보내므로 알림 피로가 누적되고 주의도가 낮아진다.

핵심 문제는 실종자의 위치를 시민 앱이 단정적으로 예측하지 못하는 데 있지 않다. **마지막 확인 정보에 근거해, 지금 주변에서 해당 인물을 알아볼 가능성이 있는 시민에게만 행동 가능한 정보를 전달하지 못하는 것**에 있다.

이는 “사람을 찾는 AI”가 아니라, 실종 초기의 중요한 시간을 놓치지 않도록 **시민의 주의와 제보를 연결하는 사람을 살리는 AI**의 문제다.

## 3. 해결책

NearFind는 공식 실종 정보의 마지막 확인 위치와 시각을 바탕으로 **알림 우선 구역**을 만들고, 그 구역에 진입하거나 체류 중인 위치정보 동의 사용자에게만 인상착의 중심의 푸시 알림을 보낸다.

푸시에는 다음 정보를 짧고 명확하게 제시한다.

- 의복, 가방, 신발, 헤어스타일, 키 등 인상착의 기반 참고 이미지
- 마지막 확인 시각과 지역 수준의 위치 정보
- 주변 확인을 요청하는 한 문장 행동 안내
- 사진, 시간, 위치를 빠르게 첨부할 수 있는 공식 제보 채널 연결

이 서비스는 시민에게 수색 명령이나 실시간 위치를 공개하지 않는다. 시민이 받는 것은 “당신이 지금 이 지역에 있으므로, 주변에서 이 사람을 알아볼 수 있는지 확인해 달라”는 제한적이고 맥락 있는 요청이다.

### OpenAI 활용

- 공식 실종 문자·사건 메모에서 마지막 확인 시각·장소·착의·특징을 구조화한다.
- 텍스트형 인상착의를 의복·소지품 중심의 참고 이미지 카드로 전환한다. 얼굴을 새로 생성하거나 신원을 추정하지 않는다.
- 사건 중요도와 시민의 현재 맥락에 맞는 짧고 중립적인 푸시 문구를 생성한다.
- 시민 제보를 “직접 목격”, “닮은 사람 목격”, “관련 물건 발견”으로 정리해 운영자가 빠르게 검토할 수 있도록 돕는다. AI가 제보의 진위를 자동 판정하거나 신고를 차단하지 않는다.

## 4. 핵심 타깃과 제품 초점

### 1차 사용자

- 출퇴근, 산책, 쇼핑, 방문 등으로 알림 우선 구역을 실제로 지나가는 시민

### 운영 사용자

- 경찰, 지자체, 실종 대응 기관, 또는 기관의 공식 데이터로 사건을 등록하는 담당자

### 도입 기관

- 경찰청 및 시·도경찰청: 공식 실종경보의 보완 채널과 제보 접수 보조
- 지방자치단체: 지역 안전앱·걷기 포인트 사업·안전 인프라와의 연계
- 치매안심센터·아동보호기관·복지기관: 고위험 실종 예방 및 지역 협력망 구축

### 제품의 초점

서비스의 중심은 “실종자를 찾을 공간을 보여주는 지도”가 아니다. 공간 모델은 **누구에게 푸시를 보낼지 결정하는 내부 타게팅 엔진**이다.

> 전국에 같은 실종 문자를 뿌리는 대신, 지금 이 근처에서 해당 인물을 알아볼 수 있는 시민에게만 보낸다.

## 5. 사용자 흐름

1. 운영자가 공식 실종 정보 또는 데모용 사건 정보를 등록한다.
2. AI가 텍스트에서 인상착의, 마지막 확인 시각, 마지막 확인 위치, 행동 특징을 구조화한다.
3. AI는 얼굴을 새로 생성하지 않고, 의복과 소지품 중심의 참고 일러스트를 생성한다.
4. 마지막 확인 정보와 경과 시간을 바탕으로 알림 우선 구역을 계산한다.
5. 해당 구역에 진입하거나 체류하는 동의 사용자에게만 푸시를 보낸다.
6. 시민은 알림에서 인상착의와 지역을 확인한다.
7. 목격 가능성이 있으면 사진, 시각, 위치를 첨부해 공식 제보 경로로 전달한다.
8. 검증된 새 목격 정보가 발생하면 운영자가 알림 우선 구역을 갱신한다.

## 6. 알림 우선 구역 설계

### 원칙

- 구역은 “실종자가 여기 있다”는 예측 지도가 아니라 **알림을 우선 전달할 구역**이다.
- 마지막 확인 위치와 시각이 기본 근거다.
- 초기 MVP는 확인되지 않은 교통수단 이용을 가정하지 않고 도보 기반으로만 계산한다.
- CCTV, 카드·교통 기록처럼 시민 앱이 직접 접근할 수 없는 정보는 운영기관이 검증한 뒤에만 반영한다.
- 역이나 정류장에 가깝다는 사실만으로 대중교통 탑승 가능성을 추가하지 않는다.

### 지도 표현

단순 원형 반경 또는 도로 선만 사용하는 대신, 두 개를 결합한다.

1. **외곽 도달 영역**: 경과 시간 동안 도보로 이론상 도달 가능한 넓은 범위다. 건물이나 골목으로 들어가 멈춘 경우도 포괄한다.
2. **내부 알림 우선도**: 보행로·도로 주변, 인접 건물 출입구, 골목, 공원, 상가 등 실제 생활 공간에 우선도를 준다.

시간이 지날수록 외곽 영역은 넓어지고, 중심부의 우선도는 옅어진다. 이는 계속 걸었다는 단정이 아니라, 시간이 지나며 알림을 보내야 할 범위를 보수적으로 넓히는 정책이다.

### 입력 변수 우선순위

| 우선순위 | 변수 | 활용 방식 |
|---|---|---|
| 높음 | 마지막 확인 위치·시각 | 구역 계산의 출발점 |
| 높음 | 보행 가능한 도로·보행로·공원·건물 접근성 | 알림 구역의 형태 보정 |
| 중간 | 경과 시간, 야간 여부, 날씨 | 구역 확대 속도와 우선도 보정 |
| 중간 | 확인된 새 목격 제보 | 운영자 검증 뒤 지도 갱신 |
| 낮음 | 연령·성별 | 보행 속도의 보조 변수로만 사용 |

연령·성별만으로 반경을 확정하지 않는다. 성인의 일반 보행 속도는 연령·성별에 차이가 있으나 개인차가 크므로, 참고값일 뿐 실종 상황의 확정 근거가 아니다.

## 7. 차별점

### 1. 문자 알림을 현장 인지 경험으로 전환

텍스트 중심 인상착의를 기억하기 쉽게 시각 카드로 바꾼다. 단, 실제 얼굴을 추정 생성하지 않고 의복·소지품·체형 특징만 시각화한다.

### 2. 전국 발송이 아닌 위치·시간 기반 타게팅

수신자의 현재 맥락과 무관하게 발송하는 방식 대신, 알림 우선 구역에 있는 시민에게 필요한 시점에만 전달한다.

### 3. 수색 지도가 아닌 시민 행동 설계

정교한 위치 추정을 시민에게 공개하는 것이 아니라, “주변을 확인해 달라”는 짧은 행동 요청과 즉시 제보 흐름에 집중한다.

### 4. AI의 역할을 제한해 신뢰를 확보

AI는 문자 구조화, 인상착의 시각화, 알림 문구 생성에 사용한다. 실종자의 얼굴·정확한 위치·이동수단을 근거 없이 추론하지 않는다.

### 5. 공익 참여형 '안심 걸음'

손목닥터9988처럼, 행동 자체에 보상을 주어 일상적인 참여 습관을 만드는 공공 인센티브 모델을 적용한다. 시민이 공식 알림 구역 안의 **공개 보행로를 일정 거리 또는 시간 이상 안전하게 걸으면** '안심 걸음' 포인트를 받는다. 푸시로 인상착의 카드를 한 번 확인할 수 있으나, 포인트의 지급 조건은 발견·제보가 아니라 **구역 내 안전 보행 참여 자체**다.

이 기능의 목적은 시민을 수색자로 고용하는 것이 아니다. 실종 초기 지역에서 평소처럼 걷는 시민의 관찰 밀도를 높이고, 알림을 받은 시민이 인상착의를 한 번 더 인지하도록 만드는 공공 참여 장치다. 손목닥터9988이 포인트로 건강한 걷기 습관을 만드는 것처럼, NearFind는 포인트로 지역 안전 참여 습관을 만든다.

보상은 목격·제보 결과와 연결하지 않는다. 특정 인물을 찾아내거나 제보 건수를 늘리도록 보상하면 허위 제보와 위험한 추적을 유발할 수 있기 때문이다.

## 8. 7시간 해커톤 MVP

### 구현 범위

1. 실종 문자 또는 데모 사건 텍스트 입력
2. 인상착의, 마지막 확인 위치·시각을 구조화하는 AI 파싱
3. 의복·소지품 중심 참고 이미지 또는 일러스트 생성
4. 마지막 확인 위치와 시간 슬라이더를 바탕으로 한 알림 우선 구역 지도
5. 가상 사용자 위치가 구역에 진입했을 때 푸시 알림 시연
6. 목격 가능성 제보 폼과 공식 신고 연결 버튼

### 데모 시나리오

1. 운영자가 “검은 모자, 회색 티셔츠, 파란 가방” 등의 실종 문자 정보를 입력한다.
2. 시스템이 참고 이미지와 알림 우선 구역을 생성한다.
3. 시간 슬라이더를 움직여 구역이 점진적으로 확장되는 모습을 보여준다.
4. 가상 시민의 위치를 구역 안으로 이동시킨다.
5. 해당 시민에게만 인상착의 중심 푸시가 도착한다.
6. 시민이 목격 가능성 제보를 제출한다.

### MVP에서 제외할 것

- 실제 경찰 데이터 연동
- 실제 시민의 상시 위치 추적
- CCTV·결제·교통 데이터 수집
- 실제 얼굴 생성 또는 얼굴 인식
- 자동 신고 접수 및 자동 수색 지시
- 현금성 보상 지급과 실제 포인트 정산

## 9. 성공 지표

- 알림 우선 구역 안의 동의 사용자에게 전달된 비율
- 광역 발송 대비 불필요한 알림을 줄인 비율
- 푸시 열람 후 제보 화면으로 이동한 비율
- 제보 작성 완료율
- 마지막 확인 이후 첫 유효 제보까지 걸린 시간

## 10. 제약사항과 대응

| 제약사항 | 위험 | 대응 방안 |
|---|---|---|
| 얼굴 생성 오류 | 오인, 무고한 시민 피해 | 얼굴 생성 금지, 인상착의 참고 이미지임을 명시 |
| 위치정보 민감성 | 이용자 감시·정보 유출 우려 | 명시적 동의, 최소 수집, 로컬 지오펜싱 우선, 언제든 철회 |
| 실종자 위치 공개 | 악용 및 프라이버시 침해 | 정확한 수색 반경·실시간 위치를 시민에게 비공개 |
| 허위 제보 | 수색 자원 낭비 | 제보 신뢰도 표시, 운영기관 검토, 공식 채널 연계 |
| 과도한 푸시 | 알림 피로와 앱 이탈 | 구역·시간·사건별 빈도 제한, 동일 사건 재알림 제한 |
| 잘못된 이동 추론 | 수색 편향 | 도보 기본값, 검증된 단서만 운영 화면에서 반영 |
| 공식 데이터 부재 | 실제 서비스화 한계 | 해커톤은 가상·공개 데모 데이터 사용, 이후 기관 협력 제안 |
| 보상 설계의 부작용 | 허위 제보, 무리한 탐색, 취약 지역 접근 | 제보·발견에 보상하지 않고 안전한 공개 보행로의 공익 참여에만 제한적으로 보상 |
| 시민의 과도한 개입 | 사적 공간 진입, 대상자 직접 추적 위험 | '직접 추적하지 말고 182/112로 신고'를 명시하고, 사유지·위험 지역 미션을 금지 |

## 11. 추가로 발전시킬 사항

### 알림 신뢰도와 설명

푸시에 “마지막 확인 지점에서 약 10분 거리의 알림 우선 구역입니다”처럼 필요한 최소 근거를 제공한다. 단, 추정 경로나 정확한 확률값은 공개하지 않는다.

### 상황별 알림 문구

아동, 고령자, 인지저하 위험 등 공식 사건 분류가 있는 경우에만 행동 문구를 조정한다. 공포를 유발하는 표현보다 확인·신고 행동을 유도하는 중립적 문구를 사용한다.

### 제보 품질 개선

제보 화면에서 “직접 목격”, “닮은 사람을 봄”, “관련 물건을 발견”을 구분하고, 자동 위치·시각 첨부와 사진 블러 처리를 제공한다.

### 배터리·개인정보 친화적 지오펜싱

상시 정밀 위치 추적 대신 운영체제 지오펜싱, 대략적 위치, 사건별 만료 시간을 활용해 배터리와 개인정보 부담을 낮춘다.

### 기관용 운영 대시보드

향후에는 사건 상태, 알림 발송 수, 익명 제보 수, 검증된 목격 지점, 구역 갱신 이력을 보여주는 운영 화면으로 확장한다. 시민 앱과 수색 운영 도구는 권한과 정보를 분리한다.

### 지역 안전 파트너 알림

일반 시민만이 아니라 동의를 얻은 편의점·약국·역무원·경비실·공공시설 담당자에게는 매장·시설에서 빠르게 확인할 수 있는 별도 카드형 안내를 제공한다. 이들은 같은 장소에 오래 머무르고 주변을 지속적으로 보는 특성이 있어, 무작위 광역 발송보다 발견 가능성을 높일 수 있다. 실제 도입 시에는 기관 협약과 개인정보·업무 부담 검토가 선행되어야 한다.

### 익명 커버리지 지표

운영자는 개인의 이동 경로가 아니라, 알림 우선 구역 안에서 익명·집계된 참여자 수와 알림 확인 수만 확인한다. 이를 통해 사람이 적은 구역에만 기관 협력망을 보강하고, 불필요한 광역 푸시를 줄인다.

## 12. 공익 참여 보상 설계안

### 참여 방식

1. 사용자가 위치정보·공익 참여에 별도 동의한다.
2. 공식 실종경보의 외곽 알림 구역 안에 안전한 **안심 걸음 참여 구역**을 만든다. 이 구역은 공공 보행로·공원길처럼 접근이 안전한 길로만 구성한다.
3. 사용자가 해당 구역에 진입하면 '주변 안전 확인' 알림과 인상착의 카드를 받는다.
4. 사용자는 자신의 일상 동선 안에서 참여 구역을 일정 거리 또는 시간 이상 걸으면 포인트를 받는다.
5. 일정 조건을 충족하면 '안심 걸음' 참여 배지가 쌓이고, 지자체 정책에 따라 소액 포인트·지역 시설 혜택·자원봉사 시간 등 비현금성 보상을 받을 수 있다.

### 포인트 산정 원칙

- **보상 대상**: 공식 알림 구역 안의 안전한 공개 보행로를 실제로 걸은 참여
- **보상 제외**: 제보 건수, 사진 제출, 발견 여부, 특정 인물과의 접촉
- **측정 방식**: GPS 또는 운영체제 지오펜싱으로 참여 구역 내 보행 거리·체류 시간을 최소한으로 확인
- **상한 정책**: 동일 구역·동일 사건·하루 단위 포인트 상한으로 포인트 사냥을 방지
- **구역 공개 수준**: 시민에게는 참여 가능한 넓은 보행 구역만 보여주며, 시스템 내부의 고우선 알림 지점과 확률 히트맵은 공개하지 않음

### 안전 장치

- 보상은 제보 건수, 사진 제출, 발견 여부와 절대 연결하지 않는다.
- 야간·사유지·하천·공사장·범죄 우려 지역 등 위험 구역은 참여 구역에서 제외한다.
- 하루·사건별 참여 상한을 두며, 순위 경쟁이나 공개 리더보드를 제공하지 않는다.
- 정확한 실종자 위치는 표시하지 않고, '공식 신고 우선·직접 추적 금지'를 알림과 제보 화면에 고정한다.
- 위치 원본 기록을 장기 보관하지 않고, 포인트 산정 뒤 최소화·익명화한다.

### 해커톤 시연

실제 보상 결제 대신, 가상 시민이 안전한 공개 보행로의 참여 구역을 일정 거리 걸으면 진행률과 '안심 걸음 1회 참여' 배지가 쌓이는 화면으로 시연한다. 제보 화면에는 포인트와 무관하다는 문구를 명확히 표시한다.

## 재구성: 시민 화면 단일 흐름 (운영자 화면은 만들지 않음)

시연자가 뒤에서 프리셋 버튼 하나로 트리거만 하고, 나머지는 전부 시민 앱 화면으로 진행.

**S1. 보행 중 화면**
- 기능: 위치 이동 애니메이션(도트가 지도 위에서 움직임), 알림우선구역 밖에 있는 상태
- 구성요소: 지도, 현재 위치 도트, 상단에 아무 알림 없음
- 텍스트: 없음 또는 최소 ("이동 중")
- 전환: 시연자가 백그라운드에서 트리거 → 도트가 알림우선구역에 진입

**S2. 잠금화면 푸시 알림**
- 기능: 첫 임팩트 지점
- 구성요소: 알림 배너, 의류 썸네일, 제목
- 텍스트: "근처에서 확인이 필요합니다 · 검은 모자·회색 티셔츠·파란 가방 · 약 12분 전 이 근처 마지막 확인"
- 전환: 탭 → S3

**S3. 인상착의 3초 카드**
- 기능: 3초 안에 기억 가능한 시각 정보, 얼굴 미생성 신뢰 문구
- 구성요소: 의류/소지품 참고 이미지, 마지막 확인 시각·지역, "왜 나에게 왔는가" 한 줄, CTA 2개
- 텍스트: "이 이미지는 얼굴이 아닌 참고 이미지입니다" / "마지막 확인 지점에서 도보 약 10분 거리"
- 전환: [주변에서 봤어요] → S4

**S4. 제보 유형 선택**
- 구성요소: 직접 목격 / 닮은 사람 목격 / 관련 물건 발견
- 전환: → S5

**S5. 제보 작성 및 제출**
- 구성요소: 사진 첨부(자동 블러 옵션), 위치·시각 자동 첨부, 메모, 제출 버튼
- 텍스트: "제출 시 공식 제보 채널로 즉시 전달됩니다"
- 전환: → S6

**S6. 제출 완료 + 안심 걸음**
- 기능: 제보와 보상의 명시적 분리(문서 12번 안전장치 원칙 반영)
- 구성요소: 제보 접수 확인, 안심 걸음 배지("오늘 1회 참여 완료")
- 텍스트: "제보는 포인트와 무관합니다"

## 지도/구역 로직은 어떻게 보여줄 것인가

별도 화면으로 만들지 않는다. S3 카드 안의 한 줄("마지막 확인 지점에서 도보 약 10분 거리")로 대체하고, 발표자가 말로 "이 거리는 마지막 확인 위치·시각을 기반으로 계산된 알림우선구역 안에 있을 때만 뜬 것"이라고 설명하면 충분하다. 지도 시각화가 필요하면 발표 마지막에 정적 이미지 한 장으로만 보여주고 인터랙션은 만들지 않는다 — 개발 리소스 대비 임팩트가 낮다.

## 시간 배분 (7분 기준)

| 구간 | 시간 |
|---|---|
| S1 보행+트리거 | 30초 |
| S2 알림 | 20초 |
| S3 카드 | 1분 |
| S4~S5 제보 | 1분 30초 |
| S6 완료+안심걸음 | 40초 |
| 지도 로직 구두 설명+클로징 문장 | 1분 |

남는 2분은 질의응답이나 문제정의(2번 항목) 짧은 도입에 배분.
[이윤지] [오후 3:16] 얻대요…
[이윤지] [오후 3:16] 한번 더 돌려보고갈까요?
[이윤지] [오후 3:18] S6. 제출 완료 + 안심 걸음 (걸음수 기반)

	•	기능: 손목닥터9988처럼 걸음수 누적 자체에 보상, 제보 결과와 분리
	•	구성요소:
	•	상단: 제보 접수 확인 배너
	•	구분선 (제보 영역과 명확히 분리)
	•	오늘 걸음수 카운터 (숫자 애니메이션, 예: “2,847보”)
	•	진행바: 목표치 대비 (예: “구역 내 3,000보 달성 시 배지”)
	•	안심 걸음 배지 아이콘 (미달성 시 반투명, 달성 시 컬러)
	•	텍스트: “제보는 걸음수·포인트와 무관합니다” / “알림우선구역 안에서 안전하게 걸은 걸음이 누적됩니다”

S6-1. (선택) 걸음수 상세 화면
탭하면 들어가는 서브 화면 — 데모에 필수는 아니지만 손목닥터 느낌을 더 살리고 싶으면 추가

	•	구성요소: 원형 걸음수 게이지(손목닥터 스타일), 오늘/이번 사건 누적 구분, 배지 컬렉션(회색조 잠금 아이콘 여러 개 나열 — 참여 습관화 느낌)
	•	텍스트: “특정 인물을 찾아서 얻는 보상이 아닙니다. 이 구역을 안전하게 걸은 것 자체가 보상 대상입니다”

시연 동작
S5 제보 제출 → S6 진입 시 걸음수 숫자가 0에서 목표치까지 빠르게 카운트업 애니메이션 → 배지 컬러 전환. 이 카운트업이 “지금 이 순간 실시간으로 쌓이는 중”이라는 인상을 줌.

주의점 (문서 반영)

	•	진행바/배지는 있어도 되지만 순위·리더보드는 만들지 않음 (문서 12번 “공개 리더보드 제공하지 않는다”)
	•	걸음수 목표는 하루·사건 단위 상한이 있다는 걸 텍스트로 한 줄 명시해야 포인트 사냥 우려에 대한 대응이 화면에도 드러남 — 예: “하루 최대 참여 포인트: OO”
[이윤지] [오후 3:21] 파일: NearFind 화면명세서.md
[이윤지] [오후 3:21] # NearFind 시민 앱 데모 — 화면 명세서 (개발용)

범위: 시민 화면 6개 (S1~S6, S6-1 서브화면 포함). 운영자 화면은 이 데모 범위에 포함하지 않음.
트리거 방식: 실시간 인터랙션 대신 시연자가 백그라운드에서 발동하는 프리셋 트리거로 화면 전환. 안정성 우선.

## 공통 규칙

- 화면 전환은 모두 프리셋 트리거 기반. 실제 위치 API·헬스 API 연동 없음(데모 한정).
- 걸음수·구역 계산 값은 목데이터로 하드코딩, 애니메이션으로만 "실시간처럼" 보이게 처리.
- 얼굴 이미지 생성 절대 없음 — 모든 화면에서 의류/소지품 중심 이미지만 사용.
- 제보(S4~S5)와 보상(S6)은 데이터 모델·화면 모두 분리. 한 화면에 동시 노출 금지.

## S1. 보행 중 화면 (홈)

**목적**: 평상시 상태 → 알림 진입 직전까지의 기준선 제공

**컴포넌트**
| 요소 | 설명 | 타입 |
|---|---|---|
| 지도 배경 | 정적 지도 이미지 또는 지도 SDK | Map |
| 현재 위치 도트 | 좌→우 또는 지정 경로로 서서히 이동하는 애니메이션 | AnimatedMarker |
| 상단 상태바 | 알림 아이콘(비활성 상태, 배지 없음) | Icon |
| 하단 텍스트 | "이동 중" 또는 공백 | Text (optional) |

**상태**
- `idle`: 도트가 알림우선구역 밖에 위치
- `entering`: 트리거 발동 시 도트가 구역 경계를 통과 (약 1.5초 애니메이션)

**전환 조건**
- 트리거 버튼(개발자용 히든 버튼 또는 시연자 키 입력) → `entering` 완료 즉시 → **S2**

**데이터**
```json
{ "user_location": {lat, lng}, "zone_boundary": [geojson polygon], "trigger": false }
```

## S2. 잠금화면 푸시 알림

**목적**: 첫 임팩트. 실제 OS 알림처럼 보이게 재현

**컴포넌트**
| 요소 | 설명 |
|---|---|
| 알림 배너 UI | OS 스타일 모방 (아이콘+타이틀+본문 1줄) |
| 의류 썸네일 | 작은 정사각 이미지 (인상착의 대표 이미지) |
| 타이틀 | "근처에서 확인이 필요합니다" |
| 본문 | "검은 모자·회색 티셔츠·파란 가방 · 약 12분 전 이 근처 마지막 확인" |

- 스와이프 제거 시: 데모에서는 비활성화 (탭만 허용)

**데이터**
```json
{
  "notification": {
    "title": "근처에서 확인이 필요합니다",
    "body": "검은 모자·회색 티셔츠·파란 가방 · 약 12분 전 이 근처 마지막 확인",
    "thumbnail_url": "..."
  }
}
```

## S3. 인상착의 3초 카드

**목적**: 3초 내 기억 가능한 시각 정보 제공 + 신뢰 확보 문구

**컴포넌트**
| 요소 | 설명 | 타입 |
|---|---|---|
| 참고 이미지 | 의류/소지품 일러스트 (얼굴 없음) | Image |
| 면책 문구 | "이 이미지는 얼굴이 아닌 참고 이미지입니다" | Text (고정, 굵게) |
| 마지막 확인 정보 | 시각 + 지역명(행정동 수준) | Text |
| 거리 설명 | "마지막 확인 지점에서 도보 약 10분 거리" | Text |
| CTA 버튼 1 | "주변에서 봤어요" (Primary) | Button → S4 |
| CTA 버튼 2 | "182·112 신고 안내" (Secondary) | Button → 외부 안내 모달 |

**레이아웃 순서 (위→아래)**
1. 참고 이미지 (화면 상단 40%)
2. 면책 문구 (이미지 바로 아래, 작은 글씨)
3. 마지막 확인 시각/지역
4. 거리 설명 한 줄
5. CTA 버튼 2개 (하단 고정)

**데이터**
```json
{
  "reference_image_url": "...",
  "last_seen_time": "12분 전",
  "last_seen_area": "OO동",
  "distance_note": "도보 약 10분 거리"
}
```

## S5. 제보 작성 및 제출

**목적**: 실제 제보 데이터 입력

**컴포넌트**
| 요소 | 설명 | 필수여부 |
|---|---|---|
| 사진 첨부 | 카메라/갤러리, 자동 블러 토글 옵션 | 선택 |
| 위치 자동첨부 | 현재 위치 자동 기록 (사용자에게는 "위치가 자동 첨부됩니다" 안내만) | 자동 |
| 시각 자동첨부 | 타임스탬프 자동 기록 | 자동 |
| 메모 입력창 | 짧은 텍스트 (최대 100자 권장) | 선택 |
| 안내 문구 | "제출 시 공식 제보 채널로 즉시 전달됩니다" | — |
| 제출 버튼 | Primary CTA | — |

**인터랙션**
- 제출 버튼 탭 → 로딩 애니메이션(1초 내외) → S6 전환

**데이터**
```json
{
  "report_id": "uuid",
  "report_type": "이전 화면에서 전달받음",
  "photo_url": "optional, blurred: bool",
  "auto_location": {lat, lng},
  "auto_timestamp": "ISO8601",
  "memo": "string, optional"
}
```

## S6. 제출 완료 + 안심 걸음

**목적**: 제보 접수 확인 + 걸음수 기반 보상 노출. 두 영역은 시각적으로 반드시 분리.

**레이아웃 (위→아래, 구분선으로 명확히 분리)**

**영역 A — 제보 접수 확인**
| 요소 | 설명 |
|---|---|
| 완료 배너 | "제보가 접수되었습니다" + 체크 아이콘 |
| 접수 번호 | 참고용 짧은 ID 표시(선택) |

**구분선**

**영역 B — 안심 걸음**
| 요소 | 설명 | 타입 |
|---|---|---|
| 걸음수 카운터 | 숫자, 0 → 목표치 카운트업 애니메이션(예: 0 → 2,847보, 약 1.5초) | AnimatedCounter |
| 진행바 | 목표치(예: 3,000보) 대비 현재값 | ProgressBar |
| 배지 아이콘 | 미달성 시 회색조, 달성 시 컬러 전환 | Icon (state: locked/unlocked) |
| 안내 문구 1 | "제보는 걸음수·포인트와 무관합니다" | Text (고정, 굵게) |
| 안내 문구 2 | "알림우선구역 안에서 안전하게 걸은 걸음이 누적됩니다" | Text |
| 하루 상한 문구 | "하루 최대 참여 포인트: OO" | Text (작은 글씨) |
| 상세 보기 버튼 (선택) | 탭 시 S6-1로 이동 | Button |

**주의 — 개발 시 반드시 지킬 것**
- 리더보드/순위 UI 없음
- 영역 A와 B 사이 데이터 연결 없음 (제보 여부와 걸음수 목표 달성은 서로 영향 안 줌)

**데이터**
```json
{
  "report_confirmation": { "status": "received", "id": "..." },
  "steps": {
    "current": 2847,
    "goal": 3000,
    "badge_unlocked": false,
    "daily_cap_note": "하루 최대 참여 포인트: OO"
  }
}
```

## S6-1. 걸음수 상세 화면 (선택, 서브화면)

**목적**: 손목닥터9988 스타일의 습관화 시각 강화. 필수 구현 아님 — 시간 남으면 추가.

**컴포넌트**
| 요소 | 설명 |
|---|---|
| 원형 게이지 | 손목닥터 스타일 도넛형 걸음수 게이지 |
| 구분 탭/텍스트 | "오늘" vs "이번 사건 누적" 구분 표시 |
| 배지 컬렉션 | 여러 개 나열, 미획득은 회색조 잠금 아이콘 |
| 하단 고정 문구 | "특정 인물을 찾아서 얻는 보상이 아닙니다. 이 구역을 안전하게 걸은 것 자체가 보상 대상입니다" |

**인터랙션**
- 뒤로가기 → S6으로 복귀

## 개발 우선순위 (7시간 MVP 기준)

1. **필수**: S1, S2, S3, S4, S5, S6 (영역 A+B 기본형)
